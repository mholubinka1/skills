# Modernise `.pre-commit-config.yaml`: uv migration + new hooks

## Problem Statement

`.pre-commit-config.yaml` is missing several hooks the team runs as a standard suite —
`pip-audit`, `actionlint`, `validate-pyproject`, `pyproject-fmt`, `uv-export` — and carries
cruft: the `pre-commit/pre-commit-hooks` repo is listed twice (v4.6.0 and v6.0.0, both
running `trailing-whitespace` + `end-of-file-fixer`), and blank-line spacing between repo
blocks is inconsistent. Two items on the requested list are already resolved or moot here:
`shellcheck` was added in PR #58, and there is no `poetry-export` hook to remove. `uv-export`
also cannot run without a `uv.lock`, which this repo does not have — `pyproject.toml` holds
only `[tool.bandit]` and `requirements.txt` is a hand-written "no dependencies" note.

## Solution

1. Give the repo a real `uv` project: add a `[project]` table (and `[tool.uv]` marking it a
   non-package) to `pyproject.toml`, generate `uv.lock` with `uv lock`, and let `uv-export`
   own `requirements.txt` (regenerated from the lock on every commit).
2. Add the five missing hooks to `.pre-commit-config.yaml`: `pip-audit`, `actionlint`,
   `validate-pyproject`, `pyproject-fmt`, `uv-export`. `actionlint` is added even though the
   repo has no `.github/workflows/` yet — it activates when one appears.
3. Clean the config: collapse the duplicated `pre-commit-hooks` block to the single v6.0.0
   entry, and put exactly one blank line between every repo block.

## User Stories

1. As a maintainer, I want `pip-audit`, `actionlint`, `validate-pyproject`, `pyproject-fmt`,
   and `uv-export` in `.pre-commit-config.yaml` with pinned revisions, so the repo runs the
   same hook suite as the team's other repos.
2. As a maintainer, I want `pyproject.toml` to be a valid `uv` project with a `uv.lock`, so
   `uv-export` and `validate-pyproject` have something real to act on and dependency state is
   locked even though there are currently no third-party dependencies.
3. As a maintainer, I want `requirements.txt` generated from `uv.lock` by `uv-export` rather
   than hand-maintained, so it can never drift from the lockfile.
4. As a maintainer, I want the duplicate `pre-commit-hooks` repo block removed and the file's
   spacing made consistent, so the config is readable and each hook is declared once.
5. As a contributor, I want `pre-commit run --all-files` to pass cleanly on the reworked
   config, so the new hooks do not block unrelated commits with pre-existing findings.

## Implementation Decisions

### `pyproject.toml`

- Add a `[project]` table: `name = "skills"`, `version = "0.0.0"`,
  `description` (one line matching the README), `requires-python = ">=3.13"`,
  `dependencies = []`.
- Add `[tool.uv]` with `package = false` — the repo is a set of skill directories plus one
  stdlib-only script, not a distributable package, so `uv lock` must not try to build it.
- Keep the existing `[tool.bandit]` table unchanged.
- Run `pyproject-fmt` once and commit its output as the canonical formatting, so the new
  hook passes on the file it will now police.

### `uv.lock`

- Generated by `uv lock`. Committed. For zero dependencies it locks only the root project.
- No `uv-lock` pre-commit hook is added (not on the requested list). Noted as a recommended
  follow-up: without it, a future `pyproject.toml` dependency edit leaves `uv.lock` stale
  and `uv-export --frozen` fails until someone re-runs `uv lock`.

### `requirements.txt`

- Replaced by `uv export` output (`uv export --frozen --no-hashes --output-file requirements.txt`).
  For zero dependencies this is a short uv-generated header. The `uv-export` hook keeps it in
  sync on every commit.
- The old hand-written "no third-party dependencies required" comment is dropped; the empty
  export plus `dependencies = []` in `pyproject.toml` now carry that information.

### `.pre-commit-config.yaml`

- **Add**, each as its own `- repo:` block with a pinned `rev`:
  - `pip-audit` — `pypa/pip-audit`, id `pip-audit`.
  - `actionlint` — `rhysd/actionlint`, id `actionlint`.
  - `validate-pyproject` — `abravalheri/validate-pyproject`, id `validate-pyproject`.
  - `pyproject-fmt` — `tox-dev/pyproject-fmt`, id `pyproject-fmt`.
  - `uv-export` — `astral-sh/uv-pre-commit`, id `uv-export`, args
    `["--frozen", "--no-hashes", "--output-file", "requirements.txt"]`.
- Exact `rev` values for the **new** hooks: pinned to their current latest tags (obtained
  by running `pre-commit autoupdate` and taking only the new repos' results).
- **Existing** hooks (`markdownlint`, `markdown-link-check`, `codespell`, `shellcheck`,
  `mypy`, `isort`, `black`, `ruff`, `gitleaks`, `bandit`) keep their current `rev`s. A full
  `pre-commit autoupdate` was run and then reverted for these: bumping `markdownlint`
  v0.41→v0.49 rewrote every table divider across five unrelated skill files, and
  `ruff` v0.15→v0.16 raised a pre-existing `EXE001` on `sync_claude_skills.py` — churn
  outside this change's scope. A dedicated dependency-bump change can pick those up.
- **Remove** the second `pre-commit/pre-commit-hooks` block (the `rev: v6.0.0` one near the
  end); keep a single `pre-commit-hooks` block and bump its `rev` from v4.6.0 to v6.0.0 (the
  newer of the two that were present), still running `trailing-whitespace` +
  `end-of-file-fixer`.
- **Spacing**: exactly one blank line between every top-level `- repo:` block, including
  around the `local` `sync-claude-skills` block.
- `shellcheck` (`shellcheck-py`) is already present and unchanged.
- Hook ordering is not otherwise reshuffled; new blocks are grouped by concern
  (`actionlint`/pyproject hooks after `shellcheck`, `pip-audit` near `gitleaks`).
- `pyproject-fmt`'s first run rewrites `pyproject.toml`: it adds a `classifiers` list
  derived from `requires-python` and pads the `[tool.bandit]` arrays (`[ ".venv" ]`). That
  output is committed as the canonical formatting — the `classifiers` on a
  `package = false` project are inert metadata but are what the formatter emits.

### Not in scope of the diff

- No `.github/workflows/` — `actionlint` is inert until a workflow exists (explicit
  decision).
- No `uv-lock` hook.
- No change to `mypy` / `isort` / `black` / `ruff` / `bandit` / `gitleaks` / `markdownlint`
  / `codespell` hook definitions, including their `rev`s (see the scoped-autoupdate note
  above).
- No ADR — a config + lockfile change, reversible as one diff.

## Testing Decisions

- No code seam — this is tooling config. Verification is running the tools:
  - `uv lock` succeeds and produces a committed `uv.lock`; `uv export` produces the
    committed `requirements.txt`.
  - `pre-commit run --all-files` passes on the full repo with the reworked config —
    including the five new hooks. Any pre-existing finding a new hook surfaces
    (`validate-pyproject` / `pyproject-fmt` on the old `pyproject.toml`, `pip-audit` on the
    environment) is fixed in this change, not suppressed, so the suite is green on merge.
  - `pre-commit validate-config` (implicit in any run) accepts the file.
  - `actionlint` reports "no workflows" cleanly rather than erroring.
- Prior art: PR #58 added `shellcheck-py` the same way — add the block, run `--all-files`,
  fix what it flags (there, an `SC2016` waiver), keep the suite green.

## Out of Scope

- Adding real dependencies or a `[build-system]`.
- A CI workflow (deferred — see the `.github/` decision above).
- `uv-lock` hook, `uv sync` in the workflow, dependency groups.
- Reordering or re-pinning the pre-existing hooks (a full `autoupdate` was tried and
  reverted — it reformatted five unrelated files; leave it to a dependency-bump change).
- Migrating `bandit` config out of `pyproject.toml`.

## Further Notes

- `shellcheck` and "remove `poetry-export`" from the original request are no-ops here
  (already present / never existed); called out so the delivered diff isn't mistaken for
  missing them.
- Recommended follow-up: add the `uv-lock` hook (same `astral-sh/uv-pre-commit` repo) so
  `uv.lock` stays in sync with `pyproject.toml` automatically.
